Proposed public helpers `repo_context.core` plus a shared facade `context_workflow`:
- `parse_github_url(url)` -> (canonical .git URL,branch or None,subfolder or None); /tree/dev/src uses simple branch dev, subfolder src. Slash-containing branch names are unresolved; tests do not guess them.
- `build_file_tree(root,name,ignore,extensions)` -> deterministic tree string using 📂/📄 and box lines; ignores node_modules/generated directories and caller ignore predicate receiving pathlib.Path, extensions filter files. This rendering is an explicit proposed presentation convention.
- `analyze_dependencies(root)` -> (stack,Markdown details), reading requirements.txt or pyproject.toml project.dependencies; details identify the dependency file and contain its dependency entries; whitespace layout is not fixed. `is_text_file(path)` accepts UTF-8 including Turkish, rejects invalid UTF-8.
- `context_workflow.snapshot(url,extensions=...,line_limit=...,token=None,clone=...)` -> Markdown. Accept only HTTPS github.com URLs, nonnegative line limit (0 unlimited); clone(canonical_url,branch=...,token=...) returns an owned temporary checkout path. Ownership transfers to snapshot and it deletes that checkout after success/failure. Honor root .gitignore, selected subfolder/extensions, generated dirs; exclude .env* and all symlinks. Never follow escaping symlinks. Never print token. UTF-8 files in sorted order; truncated marker when necessary. Invalid URL -> ValueError before clone.
- `cli_snapshot(url,operation=...)` and `ui_snapshot(url,operation=...)` call the same injected operation and return identical Markdown. These are controller contracts; actual CLI/Streamlit event wiring still requires a manual end-to-end check.
Dependencies: Python, pytest, GitPython, gitignore-parser, TOML reader. No real cloning in tests; docs/UI integration remains separate.
- CLI/UI use context_workflow.snapshot through their common injected operation. Legacy adapters are outside this contract. Snapshot metadata identifies the canonical repository and branch; commit-hash rendering is not claimed by this interface.
