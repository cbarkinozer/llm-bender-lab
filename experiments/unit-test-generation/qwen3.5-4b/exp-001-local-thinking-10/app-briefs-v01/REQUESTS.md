# Nine whole-app request drafts

Each is one paragraph. These are reconstructed core-MVP requests, awaiting owner review.

## GitHub-insignia

Build me a local GitHub dashboard in Python with FastAPI and FastMCP for cbarkinozer. I want to start it on my Mac, open it in a browser, refresh when I choose, take screenshots and close it without hosting or paying for a service. Show my profile, received stars, repository count, languages, best repositories sorted by stars or recent code pushes, and contributions, commits, opened PRs and opened issues over the last twelve calendar months in UTC, including a daily calendar. Repository and language statistics should use my public owned repositories, excluding forks but including archived ones; calculate languages from GitHub language bytes. Explain the scope of each number, and don't turn unavailable information into zero. Use official GitHub APIs and an optional server-side token; without a token, show public data and mark contribution data unavailable. Cache the last successful complete snapshot across restarts, never fetch just because I opened the page, and preserve the old snapshot and timestamp if refresh fails. Expose refresh, activity summary and top repositories through MCP using the same data as the dashboard. Keep credentials out of outputs and saved snapshots. Make the interface clean and usable on desktop and phone widths, and include simple startup instructions; no letter grade is needed.

## ghost-box

Make me a small Python desktop email assistant called Ghost-box that runs locally on my Mac. I want to connect one Gmail or Outlook account at a time, explicitly fetch messages for a date range, browse them, search the downloaded mail by text with sender and date filters, and select messages to summarize or ask questions about using a local model. Keep downloaded emails and derived results in RAM rather than an email database. Searches and answers must make the local coverage clear; finding nothing in downloaded mail must not claim that no such email exists anywhere. Summarization should receive only the selected messages and answers should retain references to their source messages. Keep the window responsive during fetches and generation, show progress and useful errors, and let me cancel work. Let me choose a local MLX or GGUF model, reuse it for follow-ups, unload it manually or after five idle minutes, and clear downloaded mail and derived results explicitly. Changing accounts must not mix the old account's mail into the new one. No background synchronization or automatic sending is needed. Give me a practical single-window app with setup and run instructions, not just isolated functions.

## slm_test_generation

Build me a Python research pipeline for benchmarking small language models that generate tests from functions. I want to give it task records, model outputs and run configuration, execute each generated pytest suite in an isolated network-disabled environment with a time limit, and get reproducible per-task results and comparison tables. Keep raw generations unchanged and distinguish collection errors, runtime failures, timeouts and genuinely passing suites. A suite that passes without exercising a meaningful assertion must not be reported as a useful test-generation success. Record which oracle checks actually execute and distinguish trivial, weak, strong and unresolved checks using an explicit taxonomy, while keeping semantic correctness as a separate judgment. Support context/dependency metadata, aggregate with the correct eligible-task denominators, retain unsuccessful and missing observations visibly, and report mutation results with clear unconditional and conditional denominators. Save task identities, configuration and source revisions so I can trace every reported number. Keep the pipeline small and usable with documented commands and fixture-based tests, and never launch model inference or alter the frozen benchmark merely to run its own tests.

## llm-bender-lab

Make me a practical Python lab for running small language-model fine-tuning experiments reproducibly. I want to define an experiment, validate conversational training data and its train/evaluation separation, save the resolved configuration, run a short training smoke through a replaceable trainer, save its adapter and metadata, evaluate the starting model and candidate under matched settings, and get a readable before/after summary. A malformed dataset or overlapping held-out examples should stop preflight rather than quietly train. Keep experiment runs in separate directories, preserve older outputs, and record model/data revisions, seed, code identity and effective settings so I can tell what actually ran. If a run fails, retain its logs and status without claiming success. Do not require a GPU, download weights or start real training when I run the lab's own tests: use a tiny fake trainer/evaluator there, but make the workflow ready to connect to a real backend. Keep credentials and large weights out of manifests and Git, distinguish unavailable metrics from zeros, and give me simple commands for preparing, running and comparing one experiment.

## ReflexModels

Build me a small Python decision-model toolkit for applications that need quick structured decisions rather than generated paragraphs. A caller should provide shared state, a natural-language question and options defined at runtime, including Turkish labels; support binary, choice and ordered-level decisions. Return stable typed results with the original option identifiers, probabilities, selected answer and uncertainty information, and let several questions share one state without mixing their options. Keep the scorer replaceable so I can use deterministic scores in tests and later connect a local model. Validate malformed requests, duplicate options and invalid probabilities rather than silently repairing them. Provide a configurable fallback decision when confidence, margin or answerability is insufficient, and evaluation/calibration helpers that report honest metrics, including undefined cases. Preserve Unicode and stable serialization so another process can consume results, don't train or download anything merely to test the toolkit, and document a complete local example from request through scoring to response and fallback.

## codelang-detect

Make me a small zero-dependency Python tool that guesses the programming language of a code snippet without loading a model or using the network. I want both a callable library and a CLI that reads a UTF-8 file or piped text and prints the detected lowercase file extension, with unknown for empty input, whitespace or ordinary prose with no convincing code markers. Use a configurable set of weighted regex rules so stronger evidence wins rather than just the first matching language, support a documented starter set of common languages, and make ties deterministic. The CLI should give useful errors and a nonzero exit code when it cannot read its input without dumping a traceback in normal use. Include a few clear examples and install/run instructions, keep the code easy to extend, and don't promise perfect detection of inherently ambiguous snippets or tune the tests to a huge hidden benchmark.

## repo-context

Build me a Python tool that turns a GitHub repository into a readable Markdown context snapshot I can give an LLM. Let me supply a repository URL, optionally a branch and subfolder, choose file extensions and a per-file line limit, and get repository metadata, dependency summaries, a directory tree and selected text-file contents in deterministic order. Respect .gitignore and common generated/dependency directories, don't include secret environment files by default, skip non-text files, and clearly identify truncated files instead of making the snapshot look complete. Support private repositories with a token kept out of the output, show a useful error when cloning or reading fails, and clean up temporary checkouts even after failure. Give me a CLI and a simple local Streamlit page for generating and downloading the same snapshot; no hosted service is necessary. Keep the core independent of the UI so it can be checked with a small local fixture repository instead of real network requests.

## cryptocurrency-analyser

Build me a small local Python cryptocurrency research app where I can choose coin tickers and a date range, fetch historical prices, compare their cumulative returns and correlations, and view charts and a concise data summary in a browser. Start with a working price-comparison workflow rather than every possible trading indicator or a trading bot. Calculate returns relative to the first observed price for each series, preserve missing observations instead of inventing prices, omit a coin only when its whole series is missing, and label the data source, timestamps and unavailable results clearly. Let me also run it with a saved sample dataset when offline. A provider failure should show a useful error rather than fabricated zero returns, and malformed selections or unusable baselines should be explained. Keep fetching, calculations and visualization separate enough to test with deterministic fixtures, never place trades or publish posts, and make the web workflow and setup straightforward on my Mac without paid services.

## miniature-llms

Build me a small educational Python repository of working language-model components that I can run on CPU with tiny tensors and understand from the code. For the first complete version, include token embeddings, rotary position encoding, RMS normalization, a causal attention block, a feed-forward block and a tiny next-token model that composes them. Use PyTorch, keep tensors consistently batch-by-sequence-by-hidden dimension at public boundaries, make weights and dimensions configurable, and explain the role of each component without claiming this tiny model reproduces a frontier model's capability. I want numerical examples that check more than output shape, a demonstration that later tokens cannot influence earlier causal outputs, proper gradients, and saving/reloading weights without changing predictions. Include a short deterministic training demo on a tiny fixed local corpus and a generation command, with no model downloads or GPU requirement. Reject incompatible dimensions clearly and keep the implementation modular enough that I can later add other architectures; JAX, custom kernels and every advanced architecture can wait.
